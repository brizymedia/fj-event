# F&J 이벤트 블로그 작업 설명서

F&J 이벤트(펀앤조이 체육교실) 홈페이지의 **행사 준비 블로그**(`/blog/`)에 글을 올릴 때 따르는 규칙이다. HD기획 `_blog/GUIDE.md` 를 F&J 에 맞게 옮겼다. 사람이 고칠 때도 이 문서를 먼저 고친다.

- 읽는 사람: 어린이집 · 유치원 원장님과 선생님, 초등학교 선생님, 지자체 · 단체 행사 담당자.
- 목표: 네이버 · 구글 · AI 검색에서 「지역 + 운동회 · 에어바운스 · 물놀이」 검색에 걸리는 것. 광고가 아니라 **담당자가 저장해 두고 싶은 체크리스트**여야 한다.
- 원칙: 틀린 정보 한 줄이 글 한 편보다 해롭다. **확인 못 한 것은 쓰지 않는다.**

## 1. 순서

1. `node scripts/blog-plan.mjs` 로 다음에 쓸 글(지역 · 주제 · 키워드)을 받는다.
2. 글마다: `_blog/regions.json` 의 `이동 · 주의 · 현장기록` 을 읽고(지역 이야기는 거기 있는 것만), 법 · 기준 이야기는 `_blog/sources.json` 의 출처와 그 `사실` 범위 안에서만 쓴다. 사진은 `_blog/photos.json` 에서 3~4장.
3. `_blog/posts/<날짜>-<slug>.json` 을 쓴다(3장). **`근거` 칸을 반드시 채운다**(지역 글만. 지역 이름 없는 `common` 글은 생략).
4. `node scripts/blog-check.mjs --new <파일>` 이 통과할 때까지 고친다. 통과시키려고 지어낸 문장을 끼워 넣지 않는다.
5. 빌드: **`python tools/build_site.py` → `python tools/blog_shell.py` → `node scripts/build-blog.mjs`** (이 순서). build_site.py 가 sitemap.xml · llms.txt 를 덮어쓰므로 블로그 빌드는 항상 그 뒤에. `blog_shell.py` 는 build_site.py 의 머리 · 꼬리를 `_blog/shell.json` 으로 옮긴다(메뉴 · 연락처가 바뀌면 다시).
6. 커밋 · 푸시. 결과 HTML(`blog/`) 은 손으로 고치지 않는다.

## 2. 절대 쓰지 않는 것 (검사기가 일부를 막는다)

- **가격 · 단가 · 「○○원」** — 견적은 문의로 받는다. 대문 「100만 원~」 같은 시작 금액도 확인 전이라 블로그에서는 쓰지 않는다.
- **후기 · 만족도 · 고객 이름 · 학교 · 기관 이름**(「병설유치원」 같은 종류 말은 가능), 참가 인원 수, 안전 인증 · 보험 · 수상.
- 회사 경험을 늘려 말하기(「~해 왔습니다」). 현장기록에 있는 **행사 종류**로만 말한다.
- 거리 · 이동 시간 숫자 — 확인한 것이 없다. 「경기 남부 출장」으로만 쓴다.
- 동네에 지어낸 특징 붙이기, 지역 문의 통계 지어내기.
- 다른 회사 · 다른 고객 사이트 이름(HD기획 등), 「무조건 · 100%」.
- 아이들 얼굴이 크게 나온 사진, `photos.json` 에 없는 사진, 지역을 속이는 캡션.

## 3. 글 형식 (JSON)

| 칸 | 규칙 |
|---|---|
| `slug` | 한글 · 영소문자 · 숫자와 `-`, 70자 이하 |
| `date` | `YYYY-MM-DD` (오늘보다 뒤 안 됨). 파일 이름 `<date>-<slug>.json` |
| `region` | `regions.json` 의 slug (`hwaseong` `dongtan` `ansan` `osan` `siheung` `suwon` `pyeongtaek` `incheon` `gunpo`) 또는 `common` |
| `topic` | `keywords.json` 의 topic. 같은 지역에 같은 topic 은 한 번만 |
| `title` | 15~50자, 지역 이름(common 제외)과 핵심 키워드를 통째로 |
| `description` | 70~160자 |
| `keyword` | `{ "main", "sub": [] }` |
| `lead` | 80~420자, 첫 문장에 핵심 키워드와 결론 |
| `points` | 3~5개 |
| `cover` | `{ path, alt, caption }` |
| `sections` | 4~8개 `{ h2, blocks }` — blocks: `p` `ul` `ol` `table` `img` `tip` |
| `faq` | 2~6개 |
| `근거` | 지역 글은 3개 이상. regions.json 근거는 25자 이하 핵심어이고 하나 이상은 `이동 · 주의 · 현장기록` 에서 |
| `sources` | 법 · 기준 · 기관을 말했으면 필수. 공식 기관 주소는 `sources.json` 그대로 |

꾸밈은 `**굵게**` 와 `[글자](/주소)` 뿐. 사이트 안 링크는 `/contact.html#form` 처럼 `/` 로 시작해 쓰면 빌더가 쪽 깊이에 맞는 상대 경로로 바꾼다(이 사이트는 `…github.io/fj-event/` 하위 경로에 있다가 도메인으로 옮겨 가므로 절대 경로를 쓰지 않는다).
